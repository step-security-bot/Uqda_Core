# عُقَد وYggdrasil: المصدر والفروقات وحدود التوافق

## نفس الفكرة الأساسية، وصيانة مستقلة

UQDA مشتقة من كود Yggdrasil وتحتفظ بجزء كبير من تصميمه وتنفيذه: شبكة IPv6
متراكبة، هوية مشتقة من المفتاح العام، تشفير طرفي، توجيه متعدد القفزات، نظراء
مباشرون، اكتشاف LAN، واجهة TUN وإدارة محلية. هذه ليست إضافات اخترعتها UQDA.
المشروع مستقل في اسمه وصيانته، وليس إصدارًا رسميًا من فريق Yggdrasil ولا توجد
موافقة أو تزكية ضمنية منهم.

عبارة «أكثر تطورًا» وحدها ليست مقارنة قابلة للتحقق. الصحيح هو تسمية التغيير
ودليله وحدوده. لا تثبت أرقام الإصدارات المختلفة أن مشروعًا أسرع أو أكثر أمانًا.

## أمثلة تغييرات محددة في UQDA

| المجال | ما يوجد في الكود | الحد الذي يجب فهمه |
| --- | --- | --- |
| تأكيد المصافحة | [link.go](../src/core/link.go) يربط تأكيد المصافحة بالهويات وبيانات التفاوض؛ `secure=required` يرفض الطرف الذي لا يدعمه | الوضع الافتراضي يسمح بالتفاوض مع أطراف أقدم؛ ليس كل اتصال تلقائيًا في الوضع الإلزامي |
| التشخيص | [doctor](../src/admin/doctor.go) وأداة الإدارة يقدمان تقرير صحة قابلًا للقراءة وJSON | نجاح الفحص لا يساوي تدقيقًا أمنيًا مستقلًا أو ضمان وصول لكل خدمة |
| WebSocket | [تنفيذ WS](../src/core/link_ws.go) يقبل `ygg-ws` و`uqda-ws` ويقدم مسارات فحص HTTP | اختلاف اسم subprotocol ليس عزلًا للشبكة، وWSS ليس مستمعًا أصليًا |
| Windows | [المثبّت](../contrib/msi/build-msi.sh) ومعرّفات TUN ومنفذ الإدارة فُصلت عن upstream في PR #48 | هذا للكود التالي؛ ملفات v0.1.9 المنشورة لا تتغير بأثر رجعي؛ راجع [الانتقال](windows-installation.md) |
| اختبارات المثبّت | [اختبار Windows](../contrib/msi/test-coexistence.ps1) يغطي التثبيت والتحديث والحذف بجانب نسخة upstream مثبتة | يختبر x64 على runner، وليس كل أجهزة المستخدمين أو سياساتهم أو التوجيه المتزامن بين الشبكتين |

هذه أمثلة تغييرات موثقة، وليست قائمة بكل فروقات التاريخ أو ادعاء أن upstream
لا يحتوي تحسينات أخرى. تقارن كل خاصية بإصدار وكود محددين عند الحاجة.

## التوافق لا يعني تطابق الإعدادات

أسماء البرامج ومسارات الخدمات وملفات الإعداد تختلف. لا تستبدل كلمة
`yggdrasil` بـ`uqda` في كل دليل قديم وتتوقع صحة النتيجة.

- افحص النسخة المشغلة بواسطة `uqdactl getSelf`، لا اسم ملف التثبيت فقط.
- `secure=required` يحتاج دعم الطرف المقابل؛ لا تفترض أن كل نظير عام يدعمه.
- كلمة مجموعة متطابقة لا تكفي إن اختلف اشتقاق مصادقة المجموعة بين الإصدارات؛
  راجع [Group password](PROJECT_GUIDE.md#group-password) واختبر الأطراف معًا.
- منفذ الإدارة محلي ومنفصل عن منفذ peering؛ تغييره لا ينشئ شبكة خاصة.
- قائمة السماح للنظراء ليست جدار حماية لخدمات IPv6، والتشفير لا يخفي بالضرورة
  عنوان الإنترنت الحقيقي عن النظير المباشر.

## كيف استفدنا من الدوكومنت المرفقة؟

راجعت بنية أرشيف موقع Yggdrasil ذي المعرّف
`99f6fbf690970d9bbfd61795dff8d5d14730856f`: الفكرة، التثبيت، الإعداد، مرجع
الحقول، الإدارة، النظراء والخصوصية. أُعيد تنظيم مراجع UQDA حول هذه الاحتياجات
بصياغة مستقلة وروابط إلى كودها، لا نسخ المقالات التاريخية أو الصور أو هوية الموقع.

الفروقات التي تمنع النسخ الآلي:

| في الأرشيف المرفق | ما يجب قوله لـUQDA الحالية |
| --- | --- |
| صفحة الإدارة تذكر `getDHT` و`getTunTap` | ارجع إلى `uqdactl list`؛ المرجع الحالي يوثق `getTree` و`getPaths` و`getTun` |
| أمثلة طلب إدارة تضع الحقول بجانب `request` | القيم الخاصة بالأمر داخل `arguments` حسب [API](admin-api.md) |
| شرح عام للإدارة على TCP/9001 | افتراضات مرتبطة بالنظام والإصدار؛ Unix socket أو منفذ Windows الحالي، مع احترام الإعداد الموجود |
| روابط برامج هواتف وخدمات عامة upstream | لا تُقدَّم كحزم UQDA رسمية أو خدمات مضمونة؛ راجع مصفوفة المنصات |
| مقالات أداء وتوجيه قديمة | مرجع تاريخي لـupstream، وليس قياس أداء جديدًا أو إثباتًا لتنفيذ UQDA الحالي |

تبقى حقوق أصحاب الكود والمكونات محفوظة. عند نقل نص أو أصل بصري مستقبلًا،
تحقق من ترخيص ذلك الأصل؛ لا تفترض أن ترخيص الكود يغطي محتوى موقع منفصل.
